# 主题、播放器及滚动修订

2026-11-05，本地开发构建；不覆盖现有 dist 安装包。

## 入口

退出原来的客户端（包括托盘进程）后，运行项目根目录的 `Preview-Local.cmd`。它用本地 .NET 启动当前开发构建，默认静音；应用仍使用原有账号和设置目录。设置 → 通用 → 个性装扮，可选星引擎party闪亮启航。删除装扮不会覆盖原先的强调色选择。

## 本轮变化

1. 页头只绘制一条贯穿全宽的黄色边线；原图采样排除自带的 27 px 黄条。原始左侧与右侧延展纹样交叉淡化，整体仍从左向右渐透明。
2. 原始播放器布局在拿到视频 aid 后即并行加载评论。切到评论页共享在途请求，成功结果复用，失败仍能重试；旧视频/旧排序的请求不回写当前列表。
3. 视频弹幕输入与发送：Enter 或发送按钮提交，使用当前 cid、视频时间、WBI 签名及 Cookie/CSRF；请求中防重发，失败保留草稿，成功清空并在本地显示这条弹幕。输入框持有键盘焦点时控制栏保持显示。直播及本地文件不显示发送框。
4. 原“图标＋区域百分比”入口改为“弹幕设置”；弹幕开关使用描边弹幕图标，关闭态增加斜线，并提供状态工具提示与无障碍名称。百分比仍在设置弹层内显示。
5. 最大化窗口进出全屏不再主动经过 Normal 状态。原生 HWND 直接刷新到显示器/工作区边界；普通窗口进入全屏及返回仍恢复其原尺寸和位置。
6. 双人插画改为裁切铺满：横向资料卡右侧铺图，左侧渐变承托个人信息；窄卡上方也铺满图像，不再保留两侧重复纹样填边。
7. 普通鼠标滚轮也复用每帧合并的滚动驱动，累加连续输入目标，避免每个数据包都从当前位置重启动画。触控板保持原敏感度规则。视频封面限制在视口附近预取，每个 UI 批次最多启动 6 张、扫描预算约 2 ms，离屏卡片不立即启动全部图片解码。
8. 网页式小窗移动期间显示 BiliTouch 品牌过渡，约 220 ms 移动＋140 ms 原生表面稳定等待；期间不停止播放器、不销毁 VideoView、不改变音量，不把裁剪重置的原生视频表面直接暴露出来。落定后移除遮罩和帧回调。此方案使用用户授权的品牌过渡，并非声称原生视频已经可以无缝逐帧缩放。

前一轮确认继续保留：点赞＝紫发爱心角色；收藏＝蓝发兔耳角色；投币＝船长角色。成功不再重复显示右上角文字 Toast，失败和取消提示保留。

## 网页对照的边界

本次尝试 kimi-webbridge：daemon 可启动，但浏览器扩展未连接；内置浏览器加载超时。公开首页 HTTP 请求只拿到 B 站验证码页面，已保存于工作区 `.tools/tmp/bilibili-home.html`，没有据此编造网页版实现或宣称完成实时对照。

微软 WPF 官方性能说明指出，标准列表虚拟化与容器回收有助于长列表滚动：https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/optimizing-performance-controls 。当前卡片墙依然是已有的非虚拟化实现，本轮限制封面任务和合并滚动写入，未假称已改成整墙容器回收，也未据此承诺所有硬件恒定帧率。

弹幕协议参考与当前接口来源：https://github.com/Biliverse/bilibili-API-collect-backup/blob/master/docs/danmaku/action.md 。夹具验证请求字段、签名、成功/失败及切视频回包，不会向真实账号发送测试弹幕；线上发送仍以服务器响应为准。

工具另提示可更新：`kimi-webbridge upgrade`，本次未自动升级或改浏览器安装。
