# BiliTouch 0.1.8 修正说明（2026-11-06）

本版对应用户对 0.1.7 的五项反馈。主要交付是 `BiliTouch-0.1.8-setup.exe`，同时提供便携包与源码。

## 原因与修改

1. **左栏与顶部衔接**：0.1.7 将左栏图案透明度降低，只会露出更暗的侧栏底色。现在左栏与顶部共用同一底色和图案强度，左栏底色向下过渡；顶部原图字样从左边缘渐入，不在接缝处突然叠加一层颜色。移除之前各页位置不一致的金色顶部线。
2. **首次打开动态**：0.1.7 先串行等全部关注请求结束，再一次向非虚拟化列表灌入 1536 个控件。现在首 50 人与动态先显示，其余关注在后台每批最多四页自动继续读取，直到结束，仍然无需滚动触发。左侧改为受视口约束的回收式虚拟化 ListBox，批量更新期间合并未读汇总；排序 Move 不再重算整张列表的汇总。单次未读探查设请求预算，避免进入页面时回溯大量历史动态。
3. **四页布局**：首页、动态、我的、应用设置共用 PageHeaderMetrics，标题统一位于 (24,20) DIP，页头统一 112 DIP。首页、我的和设置标签位于第二行；动态操作仍在同一页头内。主题绘制只覆盖该布局行；关注直播条从页头下方开始。设置页不再将主题条放进单独的标题列，窄窗也不再应用旧版首页标签边距。未读汇总和标记已读在不足宽度时换行。
4. **双人图**：文字留在左侧，右侧按双人脸部重设缩放与焦点；边缘只做短渐变，不再用横跨整图的大面积遮罩盖住左侧角色。宽、窄窗口截图均已输出并查看。
5. **播放器与发行**：0.1.7 发布时错误启用了 IncludeNativeLibrariesForSelfExtract，LibVLC 的 DLL 和插件被塞入 exe，但加载器仍按 exe 旁的 `libvlc/win-x64` 查找。真实 errors.txt 中的 “Failed to load required native libraries” 与包内空目录吻合。0.1.8 保留外置原生 DLL/插件，发布脚本检查关键文件，并把编译 setup.exe 改成必需步骤。新增 `--verify-publish` 隔离诊断入口，可以直接运行发布程序、创建实际 PlayerWindow 并用本地静音媒体确认视频时间推进；诊断在独立目录运行，不加载用户会话，不进入单实例主流程。

## 验证依据

- 1536 人夹具：其余请求被故意挂起时，首 50 人已经可操作；释放后自动加载完整 1536 人；实际仅实例化 13 个联系人行。
- 四页的宽、窄窗标题坐标一致；关注直播内容起点在 112 DIP 页头下方。
- 本轮 332 项回归：页头/大关注列表 12、动态 112、关注/未读 53、主题 28、我的 33、上一轮专项 10、播放器网页布局 28、默认回归 56。
- 实际便携程序及 setup 解包载荷的播放验证结果、SHA-256 和文件大小清单随交付提供。验证使用原生 PlayerWindow 与 960px 本地静音视频，要求原生播放时间持续推进，不以“DLL 文件存在”代替能播放。
- 四页截图与双人图截图：`artifacts/touch-tests/recovery-*.png`；本轮测试日志位于项目上级 `artifacts/release018*.log` 和 `artifacts/header018-wide-narrow-final.log`。
