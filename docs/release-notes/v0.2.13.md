# BiliTouch 0.2.13

发布日期：2026-11-09。

这是一版**缺陷修复**，内容与 0.2.12 相同，另修掉一个让「评论图片完全点不开」的崩溃。

## 修复：点开评论图片必崩（0.2.9 起存在）

**现象**：在评论区点任意一张图片，没有任何反应，`errors.txt` 里刷：

```
System.InvalidOperationException: 指定的元素已经是另一个元素的逻辑子元素。请先将其断开连接。
   at System.Windows.FrameworkElement.ChangeLogicalParent(DependencyObject newParent)
   at System.Windows.Controls.Decorator.set_Child(UIElement value)
   at BiliTouch.Views.Controls.InlineImageGallery.Button(String label, Action action)
   at BiliTouch.Views.Controls.InlineImageGallery..ctor()
   at BiliTouch.Views.PlayerWindow.OpenCommentPicture(...)
```

**根因**：0.2.9 给图片画廊的「上一张 / 下一张」按钮套主题图标时写成

```csharp
button.Content = new SkinGlyph { ..., Child = (UIElement)button.Content };
```

`SkinGlyph` 是 `Decorator`，给它的 `Child` 赋值会走 `ChangeLogicalParent`；
而 `button.Content` 那个 `TextBlock` 的逻辑父级**已经是 Button**，
同一个元素不能有两个逻辑父级 ⇒ 构造 `InlineImageGallery` 时直接抛异常。

因为它抛在**构造函数**里，所以不是"某些图片打不开"，而是：
- 分栏布局、网页布局，**两种布局都点不开**；
- 横图、竖图、单图、多图，**全都不行**；
- 从 0.2.9（2026-11-08）起就坏了，只是之前没人点过评论图。

**修法**：先把 `button.Content` 置空断开逻辑父级，再把原来的 `TextBlock` 作为
`SkinGlyph` 的 fallback 子元素挂进去。主题图标照常显示，自定义皮肤关闭时
仍回落到原来的文字图标。

**排查范围**：全仓 `SkinGlyph` 共 41 处引用，其余 40 处都是 XAML 声明式写法
（子元素直接在标签内），不存在"元素已有逻辑父级"的问题；
程序化构造 `Decorator.Child` 的只有这一处，已修。

**回归保护**：新增 `--comment-gallery` 7 项断言，其中第一条就是
「`InlineImageGallery` 构造不得抛异常」——这条在修复前必红。

## 其余内容

与 0.2.12 一致，包括实验性的 **WPF 合成视频（vmem）** 与小窗「画面本体」变形/跟手：

- 设置 → 通用 → 「实验性：WPF 合成视频（vmem）」，重开播放器后生效；
- 滚动时视频本体连续缩小、圆角渐显、朝右栏移动，背后评论透出；松手就近收敛；
- 默认关闭：vmem 走软件解码，1080p60 实测 59.8fps 没问题，4K 可能掉帧。
