# BiliTouch 0.2.12

发布日期：2026-11-09。

这一版的主线是**触控板滚动的跟手感**，另带三个顺手修掉的真 bug。

## 触控板滚动：精密包不再"一步到位"

以前触控板（精密包）走的是"本帧把累积目标一次写完"，只有鼠标滚轮才有缓动。当时的理由是
"精密包已经很密，再缓一道就是迟滞"——但这个前提不成立：

- 触控板的包率与渲染帧率**不同频**（常见 60Hz 包 / 120Hz 屏，或反过来），每帧消费 1~2 个包，
  位移序列是"6px、12px、6px…"的台阶，不是连续曲线；
- 一部分触控板/驱动把精密手势折成 ±120 的整格包，那时它和鼠标滚轮完全同质。

于是手感表现为"手指匀速划、画面按包的节奏一顿一顿"。现在两条路统一走指数逼近，
只换时间常数：精密包 0.05 秒，整格仍是 0.12 秒。精密输入本身连续，所以拖尾必须短——
再长就真成迟滞了。

## 滚动灵敏度：两条路的换算基准终于对齐

这是**参数错误，不是灵敏度偏好**：

| 路径 | 一格/一单位 | 对 WPF 原生 |
| --- | --- | --- |
| 原生滚轮（WheelScrollLines = 3） | 48 px/格 | 基准 |
| 整格那一路 | 45 px/格 | 94% |
| 精密那一路（旧） | 0.15 px/单位 ≈ 18 px/格当量 | **37.5%** |
| 精密那一路（新） | 0.45 px/单位 ≈ 54 px/格当量 | 112.5% |

同一个手势，旧版走 6 px、新版走 18 px。滚轮一格跨 45 px 而触控板同样距离只走 17 px，
观感就是"触控板像拖着沙袋"。现在两路用一把尺子，设置页的灵敏度滑杆（25%~175%）
仍可在这把尺子上继续缩放。

## 反向小包不再把一整段手势切碎

旧实现里"方向一变"就把目标、已应用、观测值**全部清空**。而人手天然有 1~2 个单位的抖动，
加上掌根误触和横向噪声，高频流里反向小包很常见——每来一个就把目标归零重来，
一整段手势被切成若干短段，每段都要从静止重新加速。

现在方向反转只把目标**截断到当前偏移**，历史记账交给"是不是别人动过滚动条"那个判据
（它才是真正需要清空状态的场合）。

## 推荐页底部三个提示同时出现

推荐 tab 页底原来同时挂着「加载中…」「加载更多」「已经到底啦」三行，两条错叠在一起：

1. 「加载更多」**没有任何 Visibility 绑定**，永久占一行；
2. 「已经到底啦」绑的是 `Loading` 的反值，首屏一加载完 `Loading` 就是 false，于是从那一刻起永久显示。

**修法是删掉这两个，不是给它们补绑定。** 推荐流是无限流（每次请求都返回新一批，
接口层面没有"最后一页"），所以「已经到底啦」在这个 tab 恒为谎话；「加载更多」也只是
重复入口——滚到底会自动补页。

这与仓库既有处理一致：追番页页底那个「加载更多」早已删除，0.2.11 又删了动态页那个。
热门 tab 的「已经到底啦」**保留**——它走 `PopularHasMore`，接口返回不足一页就是真实终点。

## 封面：下载/解码加闸门，排队后复核"还要不要这张图"

**两道并发闸门**：下载 8、解码 min(CPU/2, 4)。原来一次铺满一屏就是 20 条 HTTP 并发、
20 个解码同时抢核，UI 线程那几次布局全排在它们后面。解码是纯 CPU，超过 4 的并发
实测只抬高单张延迟、总吞吐不变。

**排队后复核**：卡片是一被添加就发起加载的，滚动时几十上百张排队等解码名额，
轮到它们时卡片早被虚拟化面板回收给别的条目了——那一份解码纯属白干，还占着名额。

这里有一个必须绕开的坑：复核不能去问那个 `Border`。解码跑在 `ConfigureAwait(false)`
之后的后台线程上，后台线程读 `border.GetValue(...)` 会抛
`InvalidOperationException: 调用线程无法访问此对象`，而异常会被吞进"无人观察的任务"——
界面上完全没有痕迹，那一格永远灰。所以标记是一个独立对象，**只放一个 int**，
由 UI 线程写、后台线程读，全程不碰任何 DependencyObject。

每次换源换一个新标记、而不是把旧的置回 0：否则新请求清零后旧任务会以为"我还要"继续解旧图，
或者反过来旧任务看到作废标记直接放弃、新任务也跟着被放弃。

## 验证

- 全量回归 **230 项检查全绿**：`home-cover-reuse` 13、`trackpad-scroll` 33、
  `scroll-boundaries` 9、`player-comments-scroll` 12、`scroll-realization` 11、
  `dynamic` 119、`release027` 9、`scroll-ab-surfaces` 1。
- `release027` 是**直接装载真实 HomePage.xaml** 的那一组，不是拼一个类似面板——
  XAML 改错必然报 `XamlParseException`，9 项全过说明推荐 tab 那处删改没有破坏结构。
- 新增 3 条断言：解码并发上限、作废后跳过解码、**以及"没作废时必须正常解出来"**。
  最后这条是刻意加的——没有它，前一条可以被"永远返回 null"蒙混过关。
- 触控板三组测试里硬编码的 `0.15` 全部改成从标定常数推导，以后再调灵敏度不会误报成回归。
