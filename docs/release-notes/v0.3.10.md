# BiliTouch 0.3.10

面向 Windows 平板与桌面端，彻底定位并根治**直播间弹幕变多后的严重卡顿问题**，同步提供原生 **x64** 与 **ARM64** 双架构安装包。

## 核心修复与性能优化

### 1. 直播间接入主窗口硬件合成（根治分层窗口回读与 ~5 FPS 掉帧）
- 此前直播间仍使用原生 `LibVLCSharp.WPF.VideoView`，其内部将弹幕层 `LiveCanvas` 与控制栏迁入独立的 `AllowsTransparency=True`（`WS_EX_LAYERED`）透明顶层窗口。在多条弹幕铺满画面时，每帧位移都触发整窗 GPU→CPU 回读（`UpdateLayeredWindow`），且在主窗口无动画时导致 `CompositionTarget.Rendering` 失步、退化为仅靠 250ms 看门狗以 ~5 FPS 跳帧。
- 现已对齐点播播放器，默认挂载 `VmemVideoView`（`LiveVmem`）硬件合成宿主，将视频帧、画面弹幕层与控制栏全部留在主窗口硬件 D3D 交换链内同帧合成，并修复了两处覆盖层 `ElementName` 跨树绑定断裂错误。

### 2. 直播间右侧「实时弹幕」侧栏重构（单批布局 35–48ms → 3.86ms）
- **实测根因**：弹幕累计达到 500 条上限后，原先每 50ms 逐条执行最多 40 次 `Messages.Add` + `Messages.RemoveAt(0)`，使 `VirtualizingStackPanel` 已实现容器锚点回退 40 位、每批 `reusedLbis = 0` 重建整屏 10 个 10 节点复杂模板并顺序测量中间不可见条目，单批阻塞 UI 线程达 `35–48ms`（占满 >70% UI 线程）。
- **单节点 DirectWrite 直绘控件（`LiveChatRow`）**：替换每行 10 节点 + 6 绑定 + 4 `DynamicResource` + `DataTrigger` 模板，缓存时间戳 `FormattedText` 与系统默认中文优先字体（消除 `Segoe UI Variable Text` 对中文逐字回退），单行测量提速 4 倍以上。
- **稳态尾部原地 `Replace` 与 120ms 合并刷新**：在跟随最新态满 500 条上限时，底层 `List<LiveChatEntry>` 一次性切片同步全部 500 条历史，仅对尾部可见窗口槽位发出 `Replace` 通知，实现 9/9 稳态容器原地复用（0 容器重建），全屏/铺满隐藏侧栏时暂停无谓滚动排版，并缓存 `LiveChatEntry.TimeText` 与 `Identity`。

### 3. 画面弹幕稳态常驻对象池与帧间节流（`LiveOverlayRenderer`）
- 弹幕飞出屏幕左侧时改为 `Visibility.Collapsed` 归池，不再反复移出/加入 `Canvas.Children`，避免持续触发布局树重排与销毁重建 `BitmapCache` GPU 纹理。
- 新增有界突发队列，将单次批量涌入的弹幕按每渲染帧最多 3 条平滑拆散入场，消除垂直弹幕墙与单帧建树尖峰。

### 4. 直播 WebSocket 噪音包零分配预筛（`LiveDanmakuService`）
- 解压缓冲改用 `ArrayPool<byte>.Shared`，在 `JsonDocument.Parse` 之前通过 UTF-8 字节预筛直接跳过 80–90% 的非弹幕高频噪音包（礼物、进场、点赞、榜单、全站下播列表大包等），实测 2,000 个噪音包耗时仅 `1.46ms`、堆分配 `0 B`。
- 弹幕回调改为无闭包类型化队列批量派发，并对高频 `WATCHED_CHANGE` 人数更新增加 1.5s 节流。
