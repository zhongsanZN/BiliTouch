# BiliTouch 0.2.14

发布日期：2026-11-09。

这一版修两个**用户直接撞上**的问题：首页封面回滚后变灰、自动更新下载必失败。

## 1. 首页下滑再回滚，原来加载过的卡片全变灰

**现象**：首页往下滑看别的视频，再往回滑到上面，之前明明已经显示过封面的卡片现在全是灰色占位，等很久也不恢复。

**根因**在 `CoverLoader` 的"还要不要这张图"标记：

```csharp
InterestOf():       slot.Current ??= new LoadInterest();   // 只在 null 时新建
AbandonInterest():  slot.Current?.Abandon();               // 只作废，不清空槽位
```

虚拟化卡片墙回收容器时会把标记**作废**，但槽位里一直留着那个作废对象。
之后再换源，`InterestOf()` 把它原样交出去，`CoverLoader.LoadAsync` 一看
`IsAbandoned` 就立刻返回 `null` ⇒ **这一格再也不会加载封面**，永远灰着。
因为变灰的是"被回收过的容器"，而首页滑动几乎必然回收，所以表现成"滑回去全灰"。

**复现**：同一个 `Border` 连续换三次源——
第一次正常出图，**第二次（回收一次之后）永远空**。修复后三次都正常。

**修法**：作废时连槽位一起清空；`InterestOf()` 也额外判断"已作废就换新"，
双保险，避免任何路径再把作废标记传下去。

**为什么以前的测试没抓到**：`HomeCoverReuseTests` 的整墙用例**所有卡片共用同一个 URL**，
缓存里只有 1 条，永远走"热缓存"快路径，根本没经过换源/作废那条链。
新增的 `--cover-recycle` 用三个不同 URL 连续换源，修复前第二条断言必红。

## 2. 自动更新"下载失败，请检查网络后重试"

**现象**：设置里提示发现 0.2.13，点「下载并安装」立刻失败；
`errors.txt` 里是 `HttpRequestException: 下载安装包失败: HTTP 504`。

**排查**：不是用户网络问题，也不是代理问题。实测同一时刻：

| 端点 | 结果 |
|---|---|
| `github.com/.../releases/download/v0.2.13/BiliTouch-0.2.13-setup.exe`（旧代码唯一使用的地址） | **504**（所有资产、直连与代理都一样） |
| `api.github.com/repos/.../releases/assets/{id}` + `Accept: application/octet-stream` | **206 Partial Content，1.05s** |

旧代码只认一个 URL、失败一次就直接抛，所以 GitHub 这条下载链路一抖，更新就必然失败。

**修法**：
- 主链接失败后**退避重试 3 次**（504 有瞬时性）；
- 仍失败则自动切到 **API 资产端点**再试 3 次（下载内容一致，SHA-256 校验照旧）；
- 全部失败才报错，并保留最后一次的状态码，不再只说"请检查网络"。
