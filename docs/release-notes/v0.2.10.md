# BiliTouch 0.2.10

发布日期：2026-11-08。

0.2.9 修掉了「退出播放器全屏闪退」，但紧接着暴露出第二个问题：**不崩了，画面变黑**。
本版把它修好，并把这类"进程还活着、但画面没了"的问题纳入回归。

## 修复：退出全屏后视频变黑

现象：网页布局下退出播放器全屏，程序不再闪退，但视频区**永久变黑**，音频继续、进度条继续走，怎么等都不恢复。

根因（探针实测 + libvlc 日志双向确认）：

- 挂／卸网页布局都会改 `VideoSurface` 的 `HorizontalAlignment` / `VerticalAlignment`。
- 原生布局下它的 `Width` / `Height` 是 `NaN`（靠 `Stretch` 拉伸，尺寸正常）。
- 一旦改成 `Left` / `Top` 而 `Width` / `Height` 仍是 `NaN` ⇒ WPF 改为**按内容量尺寸**；
  而内容是 `VideoView`（HwndHost），没有期望尺寸 ⇒ 量成 **0×0**。
- 0×0 立刻下发一次 `SetWindowPos`，libvlc 侧就是 `VoutDisplayEvent 'resize' 0x0`
  ⇒ d3d11 销毁 pool 与 vout（日志里 `destroying useless vout` + `Win32VoutCloseWindow`）
  ⇒ **之后不再重建**。所以后一步把尺寸改回正确值也救不回来。

实测时间线（进出全屏各一次，`VideoSurface` 的尺寸序列）：

```
1386.7x924.4  →  0x0  →  962.7x541.3  →  752x423.1
                  ↑ 就是这一帧把 vout 弄没了
```

修法：

- 挂载网页布局时，在**动任何子元素之前**先钉住 `VideoSurface` 的当前实际尺寸，
  让宽／高永远不经过 0；随后正常的测量逻辑把它改成真正该有的几何。
- 卸载时把顺序改成"先切回 `Stretch`，再清 `NaN`" —— 反过来同样会经过 0×0。
- 拿不到真实尺寸（还没排过版）时**不钉**，否则会把 0 永久写进去，比原问题更难查。

## 修复：退出全屏闪退（0.2.9 遗留的收尾）

0.2.9 的三层处理保留，本版只做收尾与验证补强：

- 除零守卫保留（参数非法时返回空矩形，其余原样转发）。
- 退出全屏恢复窗口尺寸保持单次原生 `SetWindowPos`。
- 全屏切换期间推迟网页布局的挂载／卸载。

## 验证方式变了：看屏幕，不再只看播放器时间

0.2.9 的探针跑 14 轮全过却漏掉了黑屏，原因是它只检查 `player.Time` 是否推进 ——
而黑屏时解码器照常在跑、时间照常推进、`TakeSnapshot` 也有图。
**唯一能区分"有画面"和"黑屏"的是屏幕本身。**

本版给 `--verify-fullscreen` 加了屏幕取样：

- 进全屏前先量一次视频区亮度作为基线，退出全屏后每次再量一次；
- 亮度低于基线的 35% 即判为黑屏并中止；
- 每轮存一张 PNG，可以人眼复核；
- 同时记录 `VideoSurface` 的每一次尺寸变化，出现 0 宽／0 高就当场记下来。

回归里也加了对应的断言：进出全屏全程视频区不得出现 0 尺寸（去掉修复后这条断言立刻失败）。
