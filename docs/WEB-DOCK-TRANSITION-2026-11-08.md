# 网页布局视频停靠过渡修复（2026-11-08）

用户报告：大小窗切换时弹幕在原位置残留片刻；画面到达右侧小窗后又向下跳一次。

原因与修改：

- 过渡已有统一的移动状态（截图准备、截图动画、备用动画），但只用于隐藏两种控制栏。现在同一状态也隐藏 DanmakuCanvas，从截图准备开始一直保持到原生视频稳定；完成或取消后恢复显示。不修改用户的弹幕开关。
- CalculateWebVideoBounds 原先修改右栏占位的上边距和高度，随后立即读取尚未重新布局的 TransformToAncestor。截图动画拿到旧位置，原生视频落位时再次计算则得到新位置，其中上边距由 0 变为 12 DIP。现在将占位准备和坐标计算分开：先完成目标占位布局，再计算动画终点；起点读取当前视频实际位置，坐标计算不再修改布局。原生视频应用位置时同样先准备占位，并以重入保护避免布局回调重复应用。

验证：

- 构建成功，现有编译警告仍保留。
- `--web-controls-unread`：41 项通过，含新增的备用动画开始、截图准备、移动/稳定等待、小窗还原及取消时弹幕显示状态检查。
- `--web-player-layout`：31 项通过。使用本地静音视频真实播放并走截图动画，采集过渡窗口画面的最终坐标，与原生视频落点及其 250ms 后坐标比较，纵向差异小于 1 DIP；小窗还原、全屏进出、150% 界面缩放、宽矮窗口和最小窗口检查通过。

验证范围是本机测试窗口及本地媒体，不代表所有显卡、多显示器 DPI 或线上视频均已逐一验收。后续已加入截图交接的闪烁修复并纳入 0.2.8 成品，见 `RELEASE-0.2.8-2026-11-08.md`。
