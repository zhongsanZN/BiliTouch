# 网页播放控制栏、动态已读同步与音频修复复查

本轮保留了另一位 AI 已有的 0.2.4 版本及音频修复，没有重新发布安装包。

## 音频修复复查

已有修复的两个方向合理：

- 音轨参数是实际 track ID，不能把常量 0 当成“第一条音轨”。从 AudioTrackDescription 中选取可用 ID 能修正原有无效恢复。
- 松手时的一次即时检查可能落在过渡期或节流窗口，之后增加一次延迟复查，能覆盖即时检查漏掉的情形。

但 `artifacts/probes/rateaudio/Program.cs` 的 v10 探针是复刻恢复逻辑，并主动禁用音轨来制造故障。其日志能证明“模拟掉轨可以恢复”，不能证明自然发生的长按松手卡顿/断音唯一由此引起。单一环境的零 flush 观测也不足以断言所有音频输出后端和真实网络流都不存在变速中断。原报告将恢复缺陷直接称为用户现象根因，证据强度不足。

本轮额外调用了产品自身的 `HealAudioIfDead`：真实 VLC、视频与 FLAC 从音轨、内存 PCM 输出。主动关闭音轨后，产品方法恢复了原来的有效音轨，并重新收到 PCM 回调；健康音轨不会被改选。该测试不向系统扬声器播放音频。

另外修正了延迟复查的生命周期：回调只作用于安排它时的播放器和加载代次；换片或开始新一轮长按后，旧回调不再碰当前音轨。定时器回调只停止自己的实例，避免旧回调影响后来的定时器。

## 大画面与小窗的控制栏

原来只按停靠进度和最终画面宽度选择控制栏。在原生视频表面尚未移动、截图尚未完成时，旧控制栏依旧可见；小窗移动时也可能继续显示旧的紧凑控制栏。

现在两套控制栏都在截图准备/传统过渡启动时立即折叠，整个运动和原生表面稳定阶段保持隐藏。鼠标或触摸唤出控制栏也不能越过这个闸门。完成或取消过渡后，按最终大小与用户原来的隐藏状态恢复对应控制栏。

## 红点为什么重复、为什么手机没有消除

修复前的生产逻辑是：动态 ID 与本地 `dynamic_seen.json` 比对决定红点，portal 接口只补充少量作者。“全部标记已读”只写本地基准，单 UP 查看使用 `feed/space`，没有走官方动态首页的 UP 选择路径。其他端的已读状态也不能覆盖已经存在的本地基准。这解释了本地消失、手机仍在和旧内容重复亮点的机制；不能将原实现称为跨端已读同步。

### 核对的第一手来源

公开的 [B 站动态首页](https://t.bilibili.com/) 当前引用 [官方 index.ae117a6a.js](https://s1.hdslb.com/bfs/static/2233-monorepo/dyn-home/static/js/index.ae117a6a.js)。本轮只读下载公开页面及脚本，没有向网络发送用户凭据，也没有替用户清除真实账号的未读内容。

脚本中可以确认：

- 获取 UP 列表使用 `portal`，带 `up_list_more=1`。
- `up_list` 兼容数组或对象。对象里的 `items/has_more/offset` 用于分页；更多条目调用 `uplist`。
- 在动态首页选择作者，读取 `feed/all` 并带 `host_mid`、`platform=web`，而不是空间页的 `feed/space`。
- 官方界面也会先在本地改变红点；本轮实现比这个乐观更新更谨慎，读取后重新获取服务端状态确认结果。

公开脚本与定位结果在 `artifacts/unread-audit/`。kimi-webbridge 的本地守护进程因日志目录权限不可用，因此改用公开页面和静态脚本只读核对；没有通过浏览器点击真实账号内容。

### 本轮实现

- 红点以完整成功的官方 `portal/uplist` 快照为依据，同时处理 true 和 false。删除生产路径中的本地 ID 推算和本地已读清除。
- 官方仅提供有无更新，所以界面不伪造具体未读条数。
- 选择单个 UP 改用官方动态首页同一路径，随后刷新服务端红点。
- “全部标记已读”按当前未读 UP 逐个读取官方作者动态流，再刷新服务端状态。只有目标都确认无未读才显示成功；请求失败、分页失败或服务端仍有红点时不伪清除，而是提示未同步。
- 新请求覆盖旧请求；过期轮询不能在已读确认后重新点亮红点，账号变化也会丢弃旧结果。
- 其他端已经读过时，下一次成功轮询返回的 false 会清除本端旧红点。失败时保留上一次成功快照。

### 排序

实际用户配置中的 FollowSortMode 是旧值 0（最近更新），界面的三枚排序按钮已经移除。旧比较器确实允许无红点作者按发布时间夹在有红点作者之间。

现在默认未读优先，并将没有版本标记的旧默认 0 迁移为 1。未读作者严格排为最前的一整组，组内按最近更新时间；服务端批量刷新后统一重排，不在 foreach 修改期间 Move 集合。新版本显式设置的排序偏好仍保留。

## 验证与边界

- Release 构建成功，0 错误；保留既有 nullable、链接测试类型冲突及未等待调用警告。
- `--web-controls-unread`：30 项，包括真实产品音轨恢复与 PCM 回调、大小窗双向控制栏隐藏、服务器分页、新旧返回结构、失败保留、已读确认、旧响应竞争和配置迁移。
- `--follow-sort`：53 项。
- `--web-player-layout`：28 项。
- `--dynamic`：112 项。

共 223 项。日志在 `artifacts/unread-audit/`。动态接口测试使用隔离的内存 HTTP 夹具，没有操作真实账号的已读状态。

这些检查证明了请求构造、状态确认、排序和控件生命周期；尚未完成真实账号与手机之间的端到端已读验收，也没有证明自然发生的全部变速卡顿都已消失。源码和测试构建已更新，既有 dist 安装包没有被替换。
