# 首页回滚封面复用（2026-11-08）

首页使用 VirtualizingCardWallPanel 回收远离视口的控件。原先 Cover.LoadAsync 在查内存缓存之前先等待 ViewportImageQueue：即使位图已经解码，回滚后的新绑定仍需等待后台队列。缓存键又要求解码宽度完全一致，已有较大缩略图不能用于较窄卡片。内存缓存淘汰后读盘重新解码，还会因新容器没有历史而重复淡入。这些行为可产生“旧卡片又刷新”的观感，并不证明每次都发出了网络请求。

本次修改：

- 内存命中直接贴图；只有未命中的图片才进入视口加载队列，出队时再次查缓存。
- 同 URL 在 1280 像素以内已有更大解码档位时，可直接复用。原图和预览大图档位不参与跨档复用。
- 以 VideoItem 的弱键记录已经显示的封面 URL，从磁盘重新解码后也不重播入场淡入；不额外保留位图。
- 回收容器换源立即清除旧背景，避免等待时显示上一条视频的图片。

保留 32 MiB / 400 条的内存缓存预算及现有回收机制。滚动足够远后旧位图被淘汰，仍可能需要读盘重新解码；本次没有将全部历史卡片或位图永久保存在内存。

验证：

- 项目和测试程序构建通过；存在原有编译警告。
- `--home-cover-reuse`：10 项通过，覆盖位图对象复用、缓存命中绕过队列、同步恢复、磁盘回读不重播淡入，以及 80 条合成卡片墙滚动离开再返回。合成墙共用一张封面，验证复用路径，不代表真实多图片缓存压力表现。
- `--release027`：9 项通过，实际首页 XAML 的 600 条夹具首屏生成 25 张卡片，滚动到中部后仍按需生成。
- `--scroll-realization`：11 项通过，卡片菜单、评论和加载动画相关行为通过。

没有重新测量真实账号持续滚动的帧率、网络请求次数或峰值内存。后续已纳入 0.2.8 安装器与便携构建，成品核验见 `RELEASE-0.2.8-2026-11-08.md`；未覆盖用户正在运行的旧版进程。
